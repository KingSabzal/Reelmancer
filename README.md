# Reelmancer

![tests](https://github.com/KingSabzal/Reelmancer/actions/workflows/tests.yml/badge.svg)
![python](https://img.shields.io/badge/python-3.10%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)

**Reelmancer** turns a topic, a trending story or a plain URL into a finished,
upload-ready short-form video — script, narration, stock footage, captions, music,
watermark and the full SEO package for YouTube, Instagram and TikTok.

Everything it uses is free and requires no attribution, nothing is generated by an AI
video model, and every setting is entered through the interface.

The render path is deliberately simple and predictable: timed visual search queries per
segment, clip download, `set_start` / `set_end` trimming, `CompositeVideoClip`
stitching and `write_videofile` rendering. Voice, mixing, captions, watermark, pattern
interrupts and the publishing package are layered on top of that.

---

## Quick start (Windows friendly)

```bash
pip install -r requirements.txt
streamlit run app.py
```

No install step is needed: the project runs straight from a download.

Then open the **Settings** tab and paste a free
[Pexels](https://www.pexels.com/api/new/) and/or
[Pixabay](https://pixabay.com/api/key/) key, plus your LLM provider details
(9Router / [OpenRouter](https://openrouter.ai/keys) /
[NVIDIA NIM](https://build.nvidia.com/) /
[Cloudflare Workers AI](https://dash.cloudflare.com/profile/api-tokens)).

Everything is stored in `config.json`. **There is no `.env` file** — every setting is
entered through the interface.

ImageMagick is **not** required: all text is rasterized with Pillow.
FFmpeg ships with `imageio-ffmpeg` and is registered automatically.

## The five tabs

| Tab | What it does |
|---|---|
| **Discover Trends** | Pulls live trends from 9 sources, clusters them, scores virality 0-100 and generates a unique title plus a full pre-filled setting set for each one. |
| **From URL** | Paste any article, paper or wiki page. It is extracted, its facts are ranked, and the video duration is derived from how much substance the source actually has. |
| **Create Video** | Topic, style, duration, voice, caption style, watermark → rendered video. |
| **Gallery** | Every finished video with thumbnail, playback, SEO package and search / filter / statistics. |
| **Settings** | API keys, defaults, and a live connection diagnostics panel. |

### Why this layout

- **Four folders at the root** — `ui/` is what the user sees, `utility/` is what
  runs, `assets/` is disposable, `output/` is the result. Ten packages used to
  sit loose in the root; now the top level fits on one screen.
- **`ui/` stays out of `utility/`** — the interface depends on the engine, never
  the other way round. Keeping them apart makes that direction obvious, and the
  engine can be driven from a script with no Streamlit installed.
- **One package per pipeline stage** — a file's folder tells you when it runs:
  `content` writes the script, `media` fetches footage, `video` renders,
  `publishing` prepares the upload.
- **`assets/` vs `output/`** — everything in `assets/` regenerates itself, so
  deleting it costs nothing but a re-download. `output/` is the only folder
  worth backing up.
- **`diagnostics/` is not in `ui/`** — the connection checks contain no
  Streamlit code, so they run from a script or a test.

### Imports

```python
from utility.core.config_manager import get_config
from utility.video.video_pipeline import VideoPipeline
```

`utility/core/paths.py` locates the project root by walking upwards until it
finds a root marker (`pyproject.toml` or `app.py`), rather than counting parent
directories. Counting is exactly what breaks when a package moves one level
deeper, as `utility/` just did; the marker search is unaffected.

## Output file naming

Rendered videos are **not** stored under an internal id. Every exported file is named
after the exact title that goes into the YouTube upload package, with a hyphen between
every word:

| YouTube upload title | File on disk |
|---|---|
| `Why Cats Purr: 5 Reasons You Never Knew!` | `Why-Cats-Purr-5-Reasons-You-Never-Knew.mp4` |
| `🔥 10 Insane Facts About Space — #3 Broke My Brain` | `10-Insane-Facts-About-Space-3-Broke-My-Brain.mp4` |
| `Café Culture & the Naïve Traveller` | `Cafe-Culture-the-Naive-Traveller.mp4` |

The same stem is reused for the thumbnail and the SEO package, so a video and
everything belonging to it sort together:

```
output/
├── videos/       Why-Cats-Purr-5-Reasons-You-Never-Knew.mp4
├── thumbnails/   Why-Cats-Purr-5-Reasons-You-Never-Knew.jpg
├── packages/     Why-Cats-Purr-5-Reasons-You-Never-Knew.json
└── videos_metadata.json
```

Rules applied by `utility/core/naming.py`, the single place that decides what an
exported file is called:

- Accents are folded to their ASCII base letter (`Café` → `Cafe`), emoji and punctuation
  are dropped.
- The stem is capped at 120 characters and never cut mid-word.
- Duplicate titles get `-2`, `-3`, … instead of overwriting each other.
- Windows reserved device names (`CON`, `PRN`, `LPT1`, …) are made safe.
- If the model returns no usable title, the topic is used; the internal id is only ever
  the last resort, so a render is never lost because it could not be named.

`videos_metadata.json` keeps the internal `video_id` as the primary key and stores the
`file_stem` alongside it, so renaming the visible files never breaks lookup, delete or
the Streamlit widget keys — only the *files* are renamed.

## Script standards

Both script paths - the topic-based generator and the URL-based one - build their
prompts from `utility/content/script_standards.py`, so a rule is never fixed in one
and forgotten in the other.

**Satisfaction, not minutes.** YouTube now ranks on predicted viewer satisfaction
("valued watchtime": only videos a viewer would rate 4-5 stars count) rather than raw
watch time. The word target is therefore given to the model as a ceiling, not a quota,
with an explicit instruction to finish early rather than pad.

**Shorts and long-form are written differently**, because since late 2025 they are
separate discovery lanes:

| | Shorts (<120s) | Long-form |
|---|---|---|
| Hook window | **1s - the first frame** | 10s |
| Hook job | The opening words *are* the payload | Validate click, raise stakes, open loop |
| Content changes every | 5-8s | 60-90s |
| Visual changes every | 2-4s | 3-5s |
| Middle | Payoff front-loaded in the first half | Retention trap at the midpoint |
| Ending | **Loops back into the first line** | Opens a door to the next video |

The one-second Shorts hook replaces the older "first 3 seconds" rule, which came from
long-form discovery: on a swipeable feed the keep-or-swipe decision is reflexive and
lands at or before one second.

The loop ending is the strongest positive signal a Short can produce - a viewer whose
brain does not register the ending rewatches without deciding to - and it is a script
decision, not an editing one. The long-form ending instead targets session
contribution, now the leading long-form signal, so it never points off YouTube.

**Content interrupts and visual changes are separate settings.** They were previously
one number. A change of *content* every four seconds would be incoherent in a
ten-minute video, while a *cut* every ninety seconds would feel static.

**Six narrative formats, rotated between videos:**

| Format | Typical retention |
|---|---|
| Story / case study | 50-65% |
| Investigation / mystery | 50-60% |
| Explainer, Tutorial | 45-55% |
| Versus / comparison | 42-52% |
| Listicle / ranking | 38-48% |

Story is weighted highest because it retains best. The format is steered by video style
(a tutorial never becomes a listicle) and biased away from whatever the last few videos
used. Recency is a weight penalty rather than an exclusion, because hard exclusion with
a small candidate pool produces a predictable A-B-C-A-B-C cycle, which is just a slower
template.

Rotation is a **compliance** measure as much as a quality one: YouTube's inauthentic
content policy names channels whose videos differ only superficially, and enforcement
is channel-wide.

**Also enforced in both paths:** the hook is written last so it can only promise what
the script delivers; no stock scaffolding ("buckle up", "let's dive in"); write for the
ear with sentences under 15 words; one call to action, never two; and for Shorts, the
opening claim is added to on-screen text because most Shorts are watched muted.

## Footage matching and clip joins

**Relevance beats a convenient duration.** Pexels and Pixabay return results in
relevance order. That order used to be discarded and the results re-sorted purely by
how close each clip was to 15 seconds, so an unrelated 14 second clip beat a well
matched 30 second one. Ranking is now relevance-first, with duration only separating
clips of similar relevance. This costs no extra API calls: it reorders results already
in hand.

**Proper nouns survive into the search.** If the script is about a specific person,
place or event, that name must appear in at least one keyword per segment. Without the
rule a segment saying "the president" searched for `president` and returned any
president in the world.

**No black flashes at the cut.** Clips are composited onto a black canvas, so any
moment the timeline is not covered shows as a black flash. Three separate causes were
found and fixed:

| Cause | Fix |
|---|---|
| A gap at the very start had nothing before it to merge into | Backward fill: borrow the first clip that exists |
| A run of gaps at the start silently dropped the rest of the run | The whole run is kept as one interval before filling |
| A clip that failed to download left its slot empty, despite the log claiming otherwise | The previous shot is genuinely extended over it |

On top of that, consecutive shots now overlap by `JOIN_OVERLAP_SECONDS` (0.07s, two
frames at 30 fps). Without the overlap a one-frame rounding difference between the
outgoing clip ending and the incoming clip starting exposes the background. The overlap
sits underneath the next clip, so nothing is visibly duplicated.

Verified by rendering a real portrait file and scanning all 255 frames: zero black
frames.

## Thin sources

A short page is the one case where writing from the source alone forces the
model to invent the difference. A 102 word stub asked to fill 60 seconds needs
about 140 spoken words, so roughly half the script would be made up, and for a
historical or political subject that means invented history.

Three things happen when a page is under 250 words:

**The pages it links to are checked** — but only accepted when they actually
name the subject. Measured on `en.wikipedia.org/wiki/Dad_Shah`:

| Linked page | Words | Names the subject | Verdict |
|---|---|---|---|
| Dadshah (film about him) | 308 | 8 times | accepted |
| Insurgency in Balochistan | 8000 | never | rejected |
| Mohammad Reza Pahlavi | 8000 | never | rejected |
| Baloch people | 8000 | never | rejected |

Following links blindly would bury 102 relevant words under 24000 irrelevant
ones and quietly change what the video is about. The relevance test keeps the
one useful page and rejects the rest. Oversized pages are skipped even when they
do mention the subject, because a survey that names someone once is still mostly
about something else. Transliteration variants are matched, so "Daad Shah" on a
related page still counts as "Dad Shah".

**The duration is capped by what the source can support.** The recommendation is
now the smaller of what the material deserves and what it can honestly fill,
measured in fact-bearing words rather than raw page length. Navigation, link
lists and citation lines no longer inflate the estimate.

**The script generator is told to stay inside the brief.** The prompt forbids
adding dates, names, numbers, causes or outcomes that are not in the source, and
instructs the model to write shorter rather than pad.

On the example above the result is 3 facts and an unflagged 60 second
recommendation becoming 8 sourced facts and a flagged 87 seconds, with the
supporting page listed in the interface.

## Guarantees

| Rule | How it is enforced |
|---|---|
| 100% free, no paid service | No ElevenLabs / Deepgram / Runway / Suno / Midjourney anywhere. EdgeTTS + faster-whisper (base, int8) only. |
| Zero attribution | Only Pexels, Pixabay, Mixkit, Coverr, Dareful, SplitShire, Videvo free, NASA, Smithsonian, Met, Rijksmuseum, NYPL and Internet Archive. `media_manager.is_allowed_url()` hard-blocks iStock, Shutterstock, Getty, Artlist and Storyblocks even if such a link appears on an approved page. |
| No AI video generation | Real stock footage and public domain material only. |
| No color grading | `pattern_interrupt_engine` applies geometric transforms only (zoom, pan, cut, Ken Burns). No LUT, no filter. |
| English only | Interface, generated content, comments and log messages are all English; non-Latin trends are filtered out by `trend_analyzer.is_english()`. |
| Online and lightweight | No MusicGen, Riffusion, Whisper-large or Stable Audio. |
| No `.env` | Every setting goes through the UI into `config.json`. |

## Language model routing

You pick **one** provider. Reelmancer never silently switches to a different provider
behind your back — if you selected NVIDIA NIM, your requests go to NVIDIA NIM.

- Models are discovered dynamically from the provider, so the list is never stale.
- Inside the chosen provider, a failing model automatically falls back to the next one.
- A circuit breaker trips after 3 consecutive failures and reports the real cause.
- Cloudflare Workers AI filters out non-text models (whisper, bge, diffusion) so only
  usable chat models are offered.

## Encoding

Output is written to a fixed 2026 delivery spec and then verified:

```
H.264 High profile, yuv420p, BT.709
1080x1920 or 1920x1080, 30 fps, 8 Mbps
AAC-LC, 48 kHz stereo, 384 kbps
```

MoviePy appends its own `-pix_fmt` after any custom ffmpeg parameters, which silently
downgraded the profile, so a post-encode `conform_to_spec()` pass re-checks the real
file and remuxes it if the spec was not met. Bitrate is selected from
`min(width, height)`, otherwise a 1080x1920 portrait video would be charged the 4K rate.

## Trend sources (all live, none require an API key)

Google Trends RSS (15 most populous countries), Reddit RSS, YouTube trending via public
Piped/Invidious mirrors, X/Twitter trend mirrors, TikTok discovery, BBC / CNN / Reuters /
Al Jazeera / Guardian / Google News RSS, Hacker News, Product Hunt and Wikipedia
"In the news".

Reddit's `.json` endpoints now reject anonymous clients and the YouTube trending page no
longer exposes titles in plain HTML, so both use working public feeds with the direct
scrape kept as a fallback. Requests rotate through 197 user agents with per-host
learning, so a host that only accepts one particular agent is remembered.

## Connection status

The **Settings** tab opens with a live diagnostics panel. Press **Test all connections**
and every key, media source and trend source is probed with a real request:

| Status | Meaning |
|---|---|
| ok | Connected and working |
| invalid | The service rejected your key |
| missing | No key configured |
| limited | Connected, but the rate limit is currently exhausted |
| degraded | Reachable but not usable (bot protection or a layout change) |
| offline | The host could not be reached from this network |

Four readiness metrics summarise whether you can actually produce a video:
**Footage**, **Text (LLM)**, **Voice** and **Rendering**. Each key form also has a
**Save and test** button that validates just that key, and stored keys are shown masked.

Pixabay specifics handled by the checker:

- An invalid Pixabay key returns **HTTP 400**, not 401, and is reported as such.
- The access tier is detected: `fullHDURL` / `imageURL` only appear with full API access,
  so standard accounts are told images cap at 1280 px (videos are still 1920x1080).
- `X-RateLimit-Limit` / `Remaining` / `Reset` are tracked and shown as a progress bar.
- All API responses are cached for **24 hours** in `assets/api_cache/` as the Pixabay terms
  require. API keys are hashed, never written to the cache in clear text.

## Known limitations

- **Videvo** answers every user agent with a JavaScript challenge (403). It is detected
  and skipped rather than retried.
- **FreePD** is now JavaScript-rendered with no scrapable MP3 links; it reports
  `degraded` and music falls back to Pixabay and Mixkit.
- Some networks and ISPs block `reddit.com`, `feeds.bbci.co.uk`, `tiktok.com` or
  `hacker-news.firebaseio.com`. Those sources will report `offline`; that is a network
  restriction, not a bug in the application.

## Notes

- Aspect ratio is derived from duration (`<120 s` → 9:16, otherwise 16:9) and is
  read-only in the UI.
- Word count uses `int((duration / 60) * 140)` and is passed to the model.
- Trend suggestions never fall back to templates: repeats are rejected against
  `assets/trend_history.json` and regenerated with a forced different angle.
- Instagram hard-capped hashtags at 5 in December 2025 and the generator respects it;
  `#fyp` and `#viral` are stripped from TikTok because they are confirmed not to drive
  the For You feed.
- Tick **"Altered or synthetic content"** in YouTube Studio; the disclosure text is
  auto-appended to every generated description.

## What is not in this repository

`config.json` is git-ignored, so API keys are never committed. A fresh clone gets
`config.example.json` instead, and the keys are entered through the Settings tab.

`assets/` and `output/` are ignored too: fonts download themselves on first use and
finished videos stay on your machine. Only `assets/.gitkeep` is tracked, so the
folder exists after cloning.
